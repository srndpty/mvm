# 字幕編集とローカル文字起こし

字幕は文字クリップと独立した、1本の S1 トラックとして保存する。保存形式は schema 16。schema 15 以前は読み込みを拒否し、自動変換しない。

## 編集

左パネルの「字幕」で開始・終了フレームと本文を入力し、「追加」「更新」「削除」を使う。一覧は時刻を秒で表示する (`35.1–35.7`、1分以上は `1:05.3`)。編集欄の右上にも入力中のフレームを秒で示す。秒は表示用の丸めで、正確な値はフレームの欄で編集する。行を選ぶと開始位置へシークし、S1 の選択も同期する。再生位置の字幕は行の左端の緑の帯で示す。再生中は編集を禁止する。

字幕の数が多くても編集が待たされないよう、一覧の model は編集のたびに作り直さず変わった行だけを知らせ、timeline の S1 は表示範囲の字幕だけを描く。[事実] 字幕400件 (release) で移動 370 → 9 ms、カット 389 → 27 ms。再現: `MVM_SUBTITLE_PERF=1` で `mvm_test_text_ui_input` を実行。

一覧の高さはパネルの半分 (最低 180px) を既定とし、一覧の下のつまみをドラッグして変えられる。ダブルクリックで既定へ戻す。高さと共通書式の開閉はプロジェクトではなく端末の表示設定として保存する。

パネルが低い場合は内部を縦スクロールする。一覧自身にもスクロールがあり、本文・時刻・ボタンはパネル全体のスクロールで操作する。文字起こしのダイアログも、小さいウィンドウではフォーム内部をスクロールできる。共通の `BoundedScrollView`／`BoundedListView`／`BoundedFlickable` は端で止まり、バウンスしない。文字起こしの置換／追加は、固定フッターの適用ボタン横で選ぶ。

S1 はドラッグで移動し、左右端のドラッグでトリムする。clip と同じく、選択中の字幕を掴むと選択をまとめて動かし、Alt+ドラッグでは元を残して複製する (複製先を半透明で示す)。動かした先・複製先が他の字幕と重なる場合は全体を拒否する。ドラッグ確定ごとに1回の Undo を記録する。Esc でドラッグを取り消せる。パネルの本文・時刻も Esc で確定済みの値へ戻せる。「次と結合」は区間をまとめ、改行で本文を連結する。

「再生位置で分割」(timeline では選択した字幕に Ctrl+K) は区間とともに本文も前後に分ける。パネルの本文欄にカーソルを置いていればその位置で分ける。置いていなければ、区間の中の再生位置の比率に最も近い句読点・空白・改行の直後で分け、それも無ければ比率の文字位置で分ける。1文字の本文は両方に残す。

S1 の字幕はクリックで選択し、Ctrl／Shift+クリックで選択へ足し引きする。S1 の空白から左ドラッグすると、触れた字幕をすべて選ぶ (clip の矩形選択と同じ。表示範囲の外の字幕も含む)。選択が空になったとき (空白の矩形選択、Ctrl+クリックで最後の 1 件を外す、clip を選ぶ) はパネルの編集対象も外し、timeline とパネルが別の字幕を指さないようにする。Undo／Redo は字幕の複数選択も戻す (戻した Project に無い字幕は選択から外す)。clip と同じショートカットで操作できる: Delete で削除、Ctrl+C／Ctrl+X でコピー・カット、Ctrl+V で再生位置へペースト、Ctrl+D で再生位置へ複製。右クリックのメニューにも同じ操作がある。複数の字幕は先頭からの相対位置を保って貼る。既存の字幕と重なるペーストは全体を拒否する。clip を選ぶと字幕の選択は外れ、Delete とクリップボード操作の対象は常にどちらか一方になる。クリップボードは最後にコピーした種類 (clip か字幕) を貼る。

区間は `[開始, 終了)`。空本文、負の時刻、0フレームの尺、字幕同士の重複は拒否する。字幕だけのプロジェクトも尺を持ち、プレビュー・動画出力の対象になる。

「共通書式」はすべての字幕へ適用する。字幕パネルの上部 (字幕一覧の上) に折りたたみで表示し、文字 clip のエフェクトコントロールと同じ部品 (`TextStyleEditor.qml`) で編集する: フォントは一覧から選び (hover で preview)、一覧の上の検索欄に入力すると部分一致 (大文字小文字を区別しない) で絞り込む。↑↓で選び Enter で確定、Esc で閉じる。絞り込んでいない一覧の先頭には、この PC に入っている字幕向きの書体 (源真ゴシックP Bold／Heavy、LINE Seed JP Bold／ExtraBold、BIZ UDPゴシック、Noto Sans JP Black／Medium、源暎ゴシックN Bold、UD デジタル 教科書体 NP、メイリオ) を「おすすめ」として出す。一覧の上のホイールは一覧を動かし、背面のタイムラインへは渡さない。サイズ・縁の幅・余白はドラッグまたは直接入力、文字色・縁・背景は色見本または16進で指定する。揃えは左・中央・右のボタン。ドラッグ中・hover 中は Project を変えずに preview だけを描き直し、確定ごとに1回の Undo を記録する。初期値は Meiryo、64px、白文字、黒縁3px、透明背景、中央揃え、左右5%・下15%の余白。本文は出力幅に応じて日本語を折り返し、明示改行も保持する。フォント欠落や画面を超える本文は確定前にエラーにする。行ごとの書式やキーフレームは持たない。

## SRTと動画出力

SRT は UTF-8、BOM の有無、LF／CRLF、複数行本文に対応する。本文中の `<` `>` `{` `}` は普通の文字として読む (`a < b`、`std::vector<int>` など)。装飾記法 (`<b>` `<i>` `<u>` `<s>` `<font ...>` とその閉じタグ、`{\an8}` などの上書き) は未対応なので、その行を示して取り込み全体を取り消す。SRT 出力の自己検査は、SRT が表せる区間と本文だけを比べる (clip とのリンクは SRT に含めない)。「置換／追加」を選んで読み込む。時刻0を基準に配置し、番号は出力時に1から振り直す。

ミリ秒とフレームの換算は整数の有理数計算で最近傍に丸め、同率は後方へ丸める。丸め後にも尺・重複を検証する。不正な行は行番号と理由を示し、取り込み全体を取り消す。装飾タグ、位置指定などは未対応。本文や区間を保持できないSRTの出力も拒否する。

動画出力の「字幕を焼き込む」は既定オン。字幕を映像・文字クリップの上へ合成する。「字幕を表示」はプレビューと焼き込みの両方に適用し、SRT は表示設定に関係なく全字幕を出力する。

一覧は ListView で仮想化し、プレビューの全画面ラスタは現在の字幕1枚だけを保持する。書式・本文の変更でキャッシュを破棄する。書き出し時のラスタは順番に一時PNGへ保存し、全字幕の画像をメモリへ常駐させない。

## 全トラックのリップル

リップル削除、空白削除、リップルトリム、速度変更のリップルは全映像・音声トラックと S1 に対する時間挿入・削除を使う。非表示・ミュートのトラックも動かす。

境界をまたぐクリップ・字幕は分割し、削除区間内を除去して後続を詰める。挿入では後半と後続を移動する。操作対象と一緒に尺を変えたリンク相手は再処理しない。素材位置とキーをトリム規則で保持し、成立しなくなったリンクやトランジションを整理する。素材フレームで時間境界を正確に表現できない場合は、部分更新せず操作全体を拒否する。

## clip とのリンク

タイムラインクリップから文字起こしした字幕は、そのクリップにリンクする (`link_clip_id`)。音声付き動画の映像と音声のリンクと同じく、clip を横へ動かすと字幕も同じ量だけ動き、clip を削除・カットするとリンクした字幕も消える。リンク相手の映像・音声を動かしても追従する。Alt を押しながらの移動では追従しない。

- 字幕だけを動かしても (S1 のドラッグ・パネルでの編集) リンクは保つ。字幕から clip は動かさない。
- 動かした先で他の字幕と重なる移動は、部分的に動かさず操作全体を拒否する。字幕が時刻0より前へ出る移動は、clip と同じく0で止める。
- clip を分割すると、分割位置以降に始まる字幕は右半分へリンクを付け替える。分割位置を跨ぐ字幕は分割位置で 2 つに分け (本文も分ける)、前半を左、後半を右の clip へリンクする。後から片方の clip を消すと、その clip の上にあった部分だけが消える。
- clip の右クリック「リンクを解除」は映像・音声のリンクと字幕のリンクを両方外す。
- 素材の削除・トラック削除・上書きで clip が消えた場合は、字幕を残してリンクだけを外す。
- 時間の対応を変える clip の編集 (trim・リップルトリム・ロール・スリップ・スライド・レート調整・速度／デュレーション) では、リンクした字幕は素材の時刻 (音声) を保つ。編集前の clip で字幕の区間を素材の時刻へ直し、trim で切り落とした音声に掛かる部分を除き、編集後の clip で timeline へ戻す。速度を 50% にすると字幕も 2 倍の位置・長さになり、スリップでは同じ音声の位置へ動き、切り落とした音声だけの字幕は消える。置き直した字幕が他の字幕と重なる編集、音声は残っているのに frame へ丸めると 0 frame になる字幕が出る編集 (速度を上げすぎた場合) は、字幕を黙って消さずに全体を拒否する。編集前の位置から作り直すので、リップルで既にずらした字幕を二重にずらさない。
- フレーム保持の挿入は保持位置への時間の挿入でもあり、保持より後の字幕 (未リンクも) を clip と同じだけ後ろへ送る。保持位置を跨ぐリンク字幕は分割と同じく前後に分け、後半を保持の後ろの clip へリンクする。
- リップル (リップル削除・空白削除・リップルトリム・速度のリップル) の全トラック時間編集が別トラックの長い clip を二分したときは、右側の音声にあたる字幕を右側の新しい clip へリンクし直す (clip の ID ではなく、二分した系譜で決める)。左右どちらの clip を消しても、その上の字幕だけが消える。
- 上書き (clip を重ねて置く) で他の clip の端が削られた場合は、その clip にリンクした字幕を置き直さない (`docs/roadmap.md`)。
- 存在しない clip へのリンクを持つ Project は読み込みを拒否する。未リンクの字幕は項目を書かない (schema 16 のまま、既存の字幕データはそのまま読める)。

S1 のリンクした字幕は下端に細い線を表示する。

## 文字起こし

### モデルの選び方

精度を優先する。日本語では `ggml-small.bin` だと「良い挨拶」が「EISATS」のように音写へ崩れることがあり、修正量が手入力と変わらない。GPU に余裕があれば **[ggml-large-v3.bin](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-large-v3.bin) (3.1GB) を Vulkan で使う**。whisper.cpp の公開モデルの中で最大・最高精度で、これより大きいモデル (10GB 級) は whisper.cpp の配布に無い。

[事実] 2026-10-03、日本語の合成音声 7.85 秒 (「良い挨拶でしたので、今日はやり直しはやめておきましょう。はい、さっさと人間関係の今日ですからね。」) を `mvm_test_transcribe` で Vulkan 認識した結果:

| モデル | 結果 | 区切り | 所要 |
| --- | --- | --- | --- |
| small | 「いい挨拶でしたので、今日はやり直しはやめておきましょう。 はい、さっさと人間関係の今日ですからね。」 | 1区間 (0–7850ms) | 約3秒 |
| large-v3 | 「いい挨拶でしたので、今日はやり直しはやめておきましょう。」「はい、さっさと人間関係の今日ですからね。」 | 2区間 (0–3500, 4380–7120ms) | 約4秒 |

再現: `pwsh scripts/build.ps1 -Target mvm_test_transcribe` の後、`build/ucrt64-release/bin/mvm_test_transcribe.exe <音声> <作業フォルダー> <モデル> vulkan ja` (第7引数で語彙ヒント)。認識した本文と区間を標準出力へ出す。

[推測] 合成音声は雑音がなく発音も明瞭なので、small との差は実際の会話音声より小さく出ている。

### large-v3 以外のモデルの比較 (2026-10-03)

[事実] RTX 4090 で、公開データの日本語音声を同じ正規化 (NFKC、句読点・空白を除去) の CER で比べた。評価環境は `C:\ai\asr-eval` (リポジトリ外)。

| モデル | 実行系 | 放送音声 ReazonSpeech test 200件 | 読み上げ JSUT 100件 |
| --- | --- | --- | --- |
| Whisper large-v3 (beam 5) | transformers | 25.4% | 7.8% |
| Qwen3-ASR-1.7B | qwen-asr | 25.8% | 8.4% |
| Qwen3-ASR-1.7B-JA (neosophie) | qwen-asr | 26.1% | 8.1% |
| Parakeet-tdt_ctc-0.6b-ja (NVIDIA) | CrispASR 0.8.41 / Vulkan | **21.2%** | **6.4%** |

- ReazonSpeech の正解文はテレビ字幕で、言いよどみや重なった発話を省くので、絶対値は全モデルで高く出る。Parakeet-ja は ReazonSpeech で学習しているので、放送音声の差には領域の有利が含まれる。読み上げの差 (7.8 → 6.4%) の方が公平な比較である。
- 差の中身: Whisper の誤りは意味の取り違え (「木曽川」→「基礎側」、「明かりを消し」→「明かり置き」、「建立」→「混流」、「停戦会談」→「定選会談」) で、利用者の報告 (「衆参」→「中3」) と同じ種類。Parakeet-ja との違いの多くは表記の揺れ (探す／捜す、方／ほう) だった。
- 長尺 (JSUT 100文を0.6秒の無音でつないだ6.6分): Whisper 7.38%、Parakeet-ja 7.20%。Parakeet-ja は短い間で文末の句点を落とし、2文を1区間にまとめる (区間の文字数 中央値36・最大71、Whisper は16・29)。字幕に使うには単語の時刻から区切り直す必要がある。
- Cohere Transcribe 03-2026 (他社の比較で上位) は Hugging Face で利用規約への同意が必要なため未評価。タイムスタンプも出さない。
- [未検証] 利用者の実素材 (会話・固有名詞の多い長尺) での比較。

この結果を受けて、モデルは large-v3 のまま保留した。今後の改善の順序 (実素材での比較、Parakeet-ja への切り替え、区切り直し、文脈による校正など) は `docs/roadmap.md` にある。

認識はビーム探索 (beam 5、best_of 5、温度の再試行あり) で行い、「(拍手)」「♪」など発話でない注記を抑制する。前区間の本文は文脈に使わない (同じ文の繰り返しへ陥ったときに後続まで巻き込むため)。代わりに任意の「語彙ヒント」(固有名詞・専門用語、200文字まで) を全区間へ渡せる。CPU 経路は全コアを使う。

Whisper は30秒の窓へ無音を足して処理するため、最後の区間の終端が素材の末尾を越えることがある ([事実] small のビーム探索で 7850ms の素材に 8360ms)。終端だけを素材の末尾へ丸める。開始が素材の外にある区間や重なる区間は丸めずに拒否する。

### タイムラインに置いた MP3 から字幕を作る手順

1. 多言語モデル (精度重視なら上記の `ggml-large-v3.bin`、軽さ重視なら [ggml-small.bin](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-small.bin)) の配布ページで「Download file」を押し、任意のローカルフォルダへ保存する。whisper.cpp の[公式モデル案内](https://github.com/ggml-org/whisper.cpp/tree/master/models)に掲載されている配布先。日本語には `.en` の英語専用モデルを使わない。アプリ内でのモデル自動取得は行わない。
2. 再生を停止し、タイムライン上の対象クリップを右クリック→「自動字幕を生成...」を選ぶ。対象のクリップ ID を指定済みで文字起こしダイアログを開く。同名の分割クリップでも、右クリックした区間が対象になる。素材全体から作る場合は、左パネルの「字幕」→「自動文字起こし」を使う。
3. 対象を確認する。クリップ名にはトラックと配置フレームも併記する。「モデルを選択」で保存したモデルを指定する。実行経路は GPU があれば `Vulkan`、言語コードを `ja`（自動検出は `auto`）にする。固有名詞が多い場合は「語彙ヒント」に書く。モデル・実行経路・言語は次回の既定として端末に保存する。
4. 「認識開始」を押す。クリップのトリム範囲・速度・配置時刻を反映した候補を作る。結果を適用するまでプロジェクトの編集・切替は行わない。
5. 候補一覧をホイールでスクロールして本文と開始・終了 (秒も併記) を確認し、修正した行は「更新」を押す。ダイアログ表示中のホイールは背面のタイムラインへ渡さない。固定フッターで「字幕を置換」または「字幕へ追加」を選び、「候補を適用」を押す。S1 と字幕一覧に反映される。再生して同期を確認する。

`素材: <MP3の名前>` を選んだ場合は MP3 全体を認識し、「素材の配置フレーム」で挿入位置を指定する。タイムライン上の配置に合わせる場合は `クリップ:` を選ぶ。SRT は「SRT出力」、動画へ重ねる場合は書き出しの「字幕を焼き込む」を使う。

「自動文字起こし」(字幕パネルの先頭) で対象の素材またはタイムラインクリップを選び、ローカルモデル、CPU／Vulkan、言語を指定する。初回は CPU、日本語が既定で、以後は前回の指定を使う。モデルの自動ダウンロードは行わない。Vulkan が使えなければ失敗し、CPUへ暗黙に切り替えない。

素材は全音声を処理して指定フレームへ配置する。クリップはトリム範囲の原音を処理する。区間の開始が 2 秒より後なら、開始の 2 秒手前へ seek してからデコードし、先頭から区間まで全部はデコードしない。seek の後はリサンプラーの格子を先頭から読んだ場合と揃える ([事実] 揃えないと mp4/AAC で最大差 0.07、揃えると 5e-6)。mp3 は索引が無いと seek 先の時刻が推定になるので先頭から読む (デコードは 85 分で約 1.7 秒)。seek が区間の開始を越えた場合は先頭から読み直す。速度の逆数と配置時刻で認識区間を換算する。ミキサー・フェード・他クリップの音声は含めない。翻訳、話者分離、単語単位の装飾は対象外。

認識は1件のバックグラウンドジョブで実行する。進捗・キャンセルを提供する。キャンセルは音声の準備・モデルの読み込み (数 GB の読み込みの途中でも、次の読み取りで打ち切る)・認識のどの段階でも効く。結果は編集可能な候補として表示する。「字幕を置換／字幕へ追加」で明示適用するまで Project を変更しない。実行中に編集やプロジェクト切替があれば適用を拒否し、再実行を案内する。認識した素材の出どころも照合する: 認識の前後で、実体 (volume・file ID)・size・更新時刻と内容全体の hash が一致しなければ候補を作らない (size と更新時刻を保った差し替えも検出する)。内容の hash は 1 MiB ごとにキャンセルを見るので、大きな素材の hash の途中でもキャンセル・終了を待たせない。候補を確認している間の差し替えは、適用の直前に実体・size・更新時刻で検出する (GUI thread で数 GB を読まないよう、ここでは内容の hash を取らない)。キャンセル・失敗は字幕と履歴を変更しない。

責務は `src/media/transcribe`（FFmpeg による16kHzモノラル準備と whisper.cpp）、`src/project/subtitles`（時刻換算・検証・編集）、app（ジョブと候補UI）に分ける。公開インターフェースに Qt・MLT・whisper の型は出さない。

## 依存と検証

whisper.cpp は `2ca53bb45e38748d07b310eeb36245a7157ac882` を固定して UCRT64 で構築する。アプリの configure でも版とリビジョンを検査する。開発機の同じ固定版のUCRT64パッケージも使用できる。

```powershell
pwsh scripts/build-whisper.ps1
pwsh scripts/build.ps1 -WhisperRoot C:\dev\soft\mvm\build\whisper-install -Target mvm_subtitle_validation
```

通常検査は公式 build/test/lint を使う。字幕用の最小ビルド対象は `mvm_subtitle_validation`。`subtitles_contract`、`subtitle_controller_contract`、`subtitle_native_preview`、`subtitle_export_pixels`、`transcribe_negative_contract` を登録している。画素試験は開始・終了の前後フレームを実動画へ書き出して比較し、焼き込みオフと GPU 合成後の画素も検査する。ネイティブプレビュー試験では、字幕だけのタイムラインの初期表示、境界へのシーク、再生を実際の D3D11 経路で確認する。

実モデル認識は通常 CTest から独立した統合試験とする。次の試験は音声を再生せず、固定本文の発話音声を生成する。

**操作可**: 認識中も通常のPC操作ができる。CPU／GPU負荷は上がる。

```powershell
pwsh scripts/make-transcribe-fixture.ps1
pwsh scripts/test-transcribe.ps1 -Model <ローカルの多言語モデル.bin>
```

CPU／Vulkan の両方が非空の結果と妥当な時刻を返すことを検査する。文章の完全一致は要求しない。

2026-10-03 に `C:\ai\_models\ggml-small.bin` と生成済みの短い発話素材を使い、上記スクリプトで CPU／Vulkan の両経路の実認識を確認した。モデル読み取りは Whisper が正常な末尾で行う試し読みを許可し、途中で切れたヘッダー・重みや検査用の空モデルは拒否する。通常 CTest の `transcribe_model_reader_contract` と `transcribe_negative_contract` でこの区別を検査する。長い音声や個別の文章の認識精度は、この短い素材の検証とは別に確認する。
