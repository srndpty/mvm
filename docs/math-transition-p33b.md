# P3-3B: 数式 group の下地の alpha の対象を広げる

2026-10-12。[P3-3A](math-transition-p33a.md) の診断用の数式 group は、合成器が不透明な下地（alpha 255）だけを
対象にしていたため、v4 の Project では 99 clip 中 25 しか group にできなかった。下地の alpha が 255 未満でも
MLT と同じ画素を作れるかを調べ、作れる範囲へ対象を広げた。

**結果は PASS（診断用の経路として）。** 対象を「合成を始める前の下地の alpha が 1 以上」へ広げた。
v4 の Project 全体の graph では 99 clip 中 97 が group になり、4 区間とも製品の経路の pre-YUV と全画素一致、
render は 9.6〜22.6 倍になった。

製品の書き出しの経路、timeout、MLT の affine、既存の画素 oracle は変えていない。試作は observer が NULL の
製品の書き出しからは動かない。v4 の Project 全体（6840 frame）の書き出しと、製品としての受け入れは
行っていない。commit・push はしていない。P1〜P3-3A の成果物と判定は変更していない
（`math_equation_sequence_product_ui` の SegFault は未解決のまま）。

証拠は `build/math-transition-p33b-20261012/`。最終の run は `20261012-184434-final/`（`identity.json` に
binary・source・runtime の SHA-256）。`trial/` は契約を変える前の調査の run である。

## 1. 実際の下地の alpha（Task A）

group の合成の直前の下地（group の下にある全 layer を重ねた RGBA）を、MLT の経路の中で記録した。

- 「測るだけ」の mode（`--compare math-group-probe`）: member は従来の affine のまま残し、group の位置に
  何も書かない transition を植えて下地を読む。出力は製品の経路と全 frame 一致した（測ることで画素は
  変わっていない）。`trial/A-probe-*/`。
- 最終の run では、実際に合成する candidate でも同じ記録を採った（下の値は最終の run）。
- 記録は、group ごとに全部の呼び出しの集計（全画面と、その frame で見えている member の字形の範囲の
  alpha の度数）を残す。呼び出しごとの記録は 256 件までで、超えていない。

[事実] v4 の Project 全体の graph、4 区間（各 60 frame。group 2 つ × 85 回の呼び出し）:

| 区間 | 下地の alpha の最小 | 現れた値 | alpha 254 の画素（延べ） | 253 以下 | 字形の範囲の中の最小 |
| --- | --- | --- | --- | --- | --- |
| 1200〜 | 254 | 254、255 | 12,240 | 0 | 254 |
| 3400〜 | 254 | 254、255 | 65,450 | 0 | 254 |
| 5280〜 | 254 | 254、255 | 255 | 0 | 254 |
| 6500〜 | 254 | 254、255 | 2,269 | 0 | 254 |

- 255 未満の値は 254 だけだった。254 の画素は、どの区間でも字形の範囲の中にある（合成に実際に使われる）。
- group は 2 つできる。group 1（18 clip）の下地は、4 区間とも全画素が 255。group 2（79 clip）の下地は、
  4 区間のすべての呼び出しで 254 の画素を含む。
- group を切っているのは、配置が対象外の 2 clip（`まとめた右辺の分数線` とその強調。拡縮する。
  frame 4620〜6420）である。
- [推測] 254 を作っている layer: 区間 1200・3400・6500 では上の 2 clip は見えていないので、254 は
  group 1 の member（先に合成された数式）が作った画素である。区間 5280 では、2 clip と group 1 の両方が
  ありうる。画素ごとにどの layer が作ったかは記録していない。
- 申告していない上位 track の layer は 21 個（字幕、track 42）で、どれも従来の経路のままである。

## 2. alpha の対照（Task B）

固定の fixture を足した（`alpha-255`・`alpha-254`・`alpha-253`・`alpha-128`・`alpha-1`・`alpha-0`・
`alpha-ramp`・`alpha-all-nonzero`）。数式は `cmp-layers-16` と同じ 16 層（端数位置、不透明度の補間、重なり、
120 frame）で、背景だけを差し替える。背景の RGB は alpha と無関係な模様（0 も 255 も現れる）にした。
比べる相手は、同じ fixture を製品の経路（MLT の affine）で書き出した pre-YUV である。

[事実] 契約を変える前の調査（下限を実験用に 0 として合成させた。`trial/B-alpha-*/`）:

| 背景の alpha | 結果 |
| --- | --- |
| 255・254・253・128・1（一様） | 120/120 frame、全 4 channel 一致 |
| 1〜255 の全値を画面全体へ散らす（`alpha-all-nonzero`） | 120/120 frame 一致。255 個の値すべてで、MLT が背景から変えた画素が 4,287 以上あり、不一致は 0 |
| 0（一様） | **不一致**（0/120 frame） |
| 左から右へ 0〜255（`alpha-ramp`） | 不一致は背景の alpha が 0 の画素だけ。1 以上の画素は不一致 0 |

- 最初に作った `alpha-ramp` は、字形の下に来る alpha が 56〜234 の一部だけだった。全部の値を確かめるために
  `alpha-all-nonzero` を足した。
- 画素の数は、再要求された frame を含む延べの数である。

alpha 0 の反例（最小例）: `alpha-0` の frame 1、画素 (0, 0)。背景 (0, 0, 40, 0)、MLT (0, 0, 0, 0)、
合成器 (0, 0, 40, 0)。

- [事実] MLT は、下も上も alpha 0 の画素の **色を 0 に書き換える**。`alpha-0` では、MLT が背景から変えた
  画素の 99.5% が「alpha は 0 のまま色だけが変わった」画素だった。2 回書き出して結果は同じである
  （再現性はある）。
- [推測] 理由: 合成後の alpha が 0 なので、重み（上の alpha ÷ 合成後の alpha）が 0 ÷ 0 になり、色の計算結果を
  8 bit へ落とすと 0 になる（P3-1.2 の逆アセンブルの命令列からの推定。この経路そのものを命令単位で
  追ってはいない）。
- これは字形の無い画素でも起きる（layer の画像が届く範囲の全部）。字形の範囲だけを走査する合成器では
  再現しない。**alpha 0 は対象外のままにする。**
- alpha が 1 以上なら、合成後の alpha は 0 にならない。上の alpha が 0 の画素は、色も alpha も変わらない
  （alpha の書き直しが 0〜255 の全値で恒等であることは、合成器が実行時に確かめている）。

## 3. 対象の範囲（Task C）

**合成を始める前の下地の全画素の alpha が 1 以上**（`kMathGroupMinimumDestinationAlpha = 1`）。

- 根拠は 2 の実測である。1〜255 の全値が、実際の MLT の出力と一致した。0 は一致しない。
- v4 の Project に必要なのは 254 と 255 だけだった（1）。範囲は「group にできる数」からではなく、
  一致を確かめた範囲から決めた。必要な値より広いが、確かめていない値は含まない。
- 単体試験でも、下の alpha 1・2・64・128・200・253・254・255 について、既存の oracle
  （`mltSourceOver`。変更していない）と総当たりで一致することを確かめている（2,291,504 byte）。
- 対象外の下地（alpha 0 の画素が 1 つでもある）は、合成器が何も書かずに拒否し、書き出しは失敗する。
  一致にも、対象外の「成功」にも数えない。

[未検証] 下地に alpha 0 があるかどうかを、書き出しの前に判定する仕組みは無い。実行時に拒否されて
書き出しが失敗する。重ねるたびに alpha は下がらないので、V1 の素材が alpha 0 を含まなければ起きないが、
それを前もって調べる処理は入れていない。

## 4. 実装（Task D）

| file | 変更 |
| --- | --- |
| `src/media/math/math_group_compose.*` | 下限の定数、下地の alpha の最小値を求める関数、下限を明示する実験用の入口（`detail`） |
| `src/media/mlt/mvm_mlt_export.c`・`.h` | group の分け方（rule）、group ごとの空の track、clip ごとの結果の出力、下地を見せる callback |

- group の分け方に **rule 1** を足した: 合成の順だけを守る。group の最初の member より後ろ・自分より前に
  ある従来の clip と時間が重なる clip が来たら、そこで新しい group を始める。P3-3A の分け方（rule 0:
  下に従来の layer が重ならない clip だけ）も残してある。
- 順序が保たれる理由は P3-3A と同じである（member と、group の位置からその member までの間にある
  従来の clip が、同じ frame に見えない）。
- group ごとに、何も載せない track を 1 本使う。同じ track を 2 つの group が使うと、先の group が
  その track の frame を隠すので、後の group が呼ばれない（MLT の transition の仕様）。
- 配置が対象外の clip（拡縮・回転・shear・crop）、Write・変形・数式の連続・graph・字幕は、従来の経路の
  ままである。準備済みの画像（変更できない型）、複製へ合成してから差し替える方式も変えていない。
- 入口は observer の入力だけで、製品の書き出し（observer が NULL）からは有効にできない。
- MLT の affine と、既存の画素 oracle は変更していない。
