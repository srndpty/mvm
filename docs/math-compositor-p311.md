## 1. 全 frame の比較（Task A）

`pwsh scripts/math-compositor-p311-verify.ps1`。fixture ごとに製品の経路で書き出して全 frame の pre-YUV を
保持し、同じ frame を合成器で作って byte 単位で比べる（全画素・4 channel、許容差なし）。
位置と不透明度は書き出しの計画（`mapTimelineExportPlan`）のその frame の値、画像は MLT が受け取るものと
同じ（motion のある clip は qtcrop と同じ描き直しの後）を使う。補間の途中・fade の途中の frame も比べる。

[事実]

| fixture | 想定 | 観測 | 比較 | 欠落 | 対象外 | 不一致の frame |
| --- | --- | --- | --- | --- | --- | --- |
| `cmp-integer` | 120 | 120 | 120 | 0 | 0 | 0 |
| `cmp-fraction-fade` | 120 | 120 | 120 | 0 | 0 | 0 |
| `cmp-layers-16` | 120 | 120 | 120 | 0 | 0 | 0 |
| `cmp-layers-48` | 120 | 120 | 120 | 0 | 0 | **6**（各 1 画素） |
| `cmp-region-motion` | 120 | 120 | 120 | 0 | 0 | 0 |
| `cmp-region-scale` | 180 | 180 | 61 | 0 | 119 | 0 |
| `p2-window-early` | 60 | 60 | 60 | 0 | 0 | 0 |
| `p2-window-middle` | 60 | 60 | 60 | 0 | 0 | 0 |
| `p2-window-late` | 60 | 60 | 60 | 0 | 0 | 0 |

- 比べた 841 frame のうち 835 frame が全画素一致。欠落は 0。
- 対象外の 119 frame は、拡縮する layer を含む（合成器が対応していない）。一致には数えていない。
- **反例**: `cmp-layers-48`（48 層、全 frame が補間の途中の layer を含む）の frame 13、画素 (866, 556)。
  合成器 (204, 174, 174, 254)、MLT (203, 174, 174, 254)。R だけが 1 階調違う。同じ fixture の 6 frame で
  1 画素ずつ違う。最初の frame 以外の 5 frame の番号と座標は記録していない（report は最初の 1 件だけを残す）。

反例について調べたこと（`opacity-order/`）: 不透明度と `1/255` を掛ける順序を 3 通りに変えて、同じ fixture と
`cmp-region-motion` で実際の MLT と比べた。3 通りとも大きく悪化した（不一致 34〜120 frame、9,184〜590,930 画素）。
現在の順序（alpha ×（不透明度 × 1/255））が正しく、反例の原因は掛ける順序ではない。
source は書き換える前の内容へ戻し、SHA-256 の一致を確かめた。

[未検証] 反例の原因は分かっていない。P3-1 の差（qtcrop の描き直し）と同じく、赤い強調の字形の R だけが
違う。不透明度が補間の途中にある frame で起きているが、同じ条件を含む `cmp-region-motion` と v4 の 3 区間では
起きていない。

## 2. 丸めの対照（Task B）

合成器の source を 1 か所だけ書き換えて単体試験（`math_group_compose_oracle`）を実行し、元へ戻した
（`mutation/mutation-log.txt`）。

| 変異 | 結果 |
| --- | --- |
| alpha を切り捨てでなく四捨五入で 8 bit にする | build 成功、「整数位置で oracle と全 byte 一致する」で失敗 |
| 不透明度に `1/255` を掛ける代わりに 255 で割る | 同上 |
| 復元 | SHA-256 が変異の前と一致。復元後の試験は通過（491,520 byte 一致） |

どちらも意図した検査での不一致として検出された（build の失敗や timeout ではない）。
この対照が比べる相手は独立した oracle（整数位置）である。実際の MLT の出力を相手にした変異の実行は、
上の順序の実験 3 通りが該当する（いずれも大きな不一致として検出）。

## 3. 範囲（ROI）の境界（Task C）

[事実] 単体試験に、字形の範囲の右端の列をすべて不透明にした layer を足した。正しい範囲では結果が期待値と
一致し、右端の 1 列を範囲から外すと、その列が描かれずに期待値と違う（検出）。

契約（文書としての定義。型での保護は未実装）:

- 範囲は「alpha が 0 でない texel の外接矩形」で、成果物の画像ごとに 1 回だけ求める。frame ごとに
  全画面を走査し直さない（検証 harness も clip ごとに 1 回だけ求めて使い回す）。
- 範囲の外の texel は alpha 0 でなければならない。合成器はこれを確かめない。
- **未解決**: 外から渡された誤った範囲を、合成器は拒否できない（寸法の検査だけ）。誤った範囲は、上の対照の
  ように画素の不一致として現れるが、黙って受け入れられる入力であることに変わりはない。
  範囲を「準備の関数だけが作れる値」にする変更（型で保護する）は行っていない。

## 4. 制限と前処理の契約（Task D・E）

合成器が対象にしてよい入力（これ以外は、将来組み込む場合も今の MLT の経路へ残す）:

- 等倍の静止の数式だけ。拡縮・回転・shear・crop・Write・変形は対象外。
- **下地が不透明（alpha 255）であること。** 透明・半透明の下地は実際の MLT と比べていない。
  単体試験も不透明な下地だけである。上下とも alpha 0 の画素は、合成器は書かずに残す（MLT では 0 での
  割り算になる）。この挙動を「対応済み」として扱わない。
- 合成器は下地の alpha を検査しない。対象かどうかの判定は呼び出し側の責任で、まだ実装していない。

qtcrop の前処理:

- 必要な clip: 書き出しの計画で motion の frame を持つ clip（位置・拡大・回転・crop のどれかに keyframe が
  ある）。MLT 層は crop が 0 でも qtcrop を付ける。motion の無い clip には付かない。
- 前処理は、MLT の qtcrop と同じ手順（透明で塗った画像へ、全体を clip して `QPainter` で描く）で、
  Qt に依存する。合成器の外（staging の側）に置く。製品の qtcrop は外さず、出力も変えない。
- cache: crop が 0 のとき、描き直しの結果は frame によらない。全 frame の比較は clip ごとに 1 枚だけ
  作った画像で行っており、8 fixture で全 frame が一致した。したがって「成果物・色・出力の大きさ」ごとに
  1 枚を作って使い回せる。crop が 0 でない clip は対象外なので、crop の値への依存は扱わない。
- [未検証] 反例（1 の 6 画素）が、この前処理の再現の不完全さによるものかどうかは分かっていない。
