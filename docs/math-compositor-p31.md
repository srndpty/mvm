# P3-1: 数式 layer の CPU 合成を MLT の出力と byte 単位で一致させる

2026-10-12。[P3-Design](math-compositor-p3-design.md) の続き。検証 harness の中の試験的な計算は、
代表 7 frame のうち 6 frame で MLT の pre-YUV と全画素一致し、1 frame で 1 画素だけ 1 階調違っていた。
ここではその原因を特定し、MLT にも Qt にも依存しない合成器を `src/media/math` に作って、独立した oracle と
実際の MLT の出力の両方と比べた。

**製品の書き出しの経路、timeout、既存の oracle の基準は変えていない。** 合成器は製品からまだ呼ばれていない。
MLT への組み込みはしていない。commit・push はしていない。P1〜P3-Design の成果物と判定は変更していない。

証拠は `build/math-compositor-p31-20261012/`（各 directory の `identity.txt` に binary と source の SHA-256）。

## 判定

| 終了の条件 | 結果 |
| --- | --- |
| 1 画素の差の原因と修正を示す | **満たす**（下の 1） |
| 対応する範囲で byte 単位の比較に通る | 満たす。ただし MLT との比較は代表 frame 20 枚で、全 frame ではない |
| 必要な対照がすべて効く | **一部未実施**。「source-over の丸めの誤り」の対照を作っていない |
| 実装が有界で決定的 | 満たす（下の 2。ただし layer の画像は全画面のまま持つ） |
| 製品の書き出しが変わっていない | 満たす |
| provenance が最終の実装と一致 | MLT との比較は整形前の source の binary で行った。整形は空白だけの変更だが、同じ source ではない |

**全体の判定: HOLD（残り 2 点）。** 原因は特定でき、比べた範囲では許容差なしで完全一致した。
残っているのは、(a) MLT との比較を全 frame へ広げること、(b) 丸めの誤りの対照である。

## 1. 1 画素の差の原因（Task A）

[事実] 差は再現した。`cmp-region-motion` の frame 96、画素 (1108, 503)、R channel（期待 184、MLT 183。
G・B・A は一致）。別の区間（`p2-window-late` の frame 0）でも同じ種類の差が 8 画素あった
（例: (1375, 372) で R が 164 と 163）。どれも赤い強調の字形の画素で、違うのは R だけだった。

切り分け（同じ画素で差が残るかを見た。`mismatch`・`mismatch-variants`・`plan-inputs`・`qtcrop-roundtrip`）:

| 変えた点 | 結果 |
| --- | --- |
| 下の alpha を `/255` ではなく `1/255` の掛け算にする | 変わらない（同じ 1 画素・8 画素） |
| 色の積和を 1 回の丸めにする（FMA、2 通り） | 変わらない |
| 色を「下 + (上 − 下) × 重み」に組み替える | 悪化（742〜2940 画素） |
| 位置と不透明度を、書き出しが MLT へ渡す計画の値そのものにする | 変わらない |
| **motion のある clip の画像を、MLT の qtcrop と同じ手順で描き直す** | **差が消えた**（7 fixture・16 frame が全画素一致） |

原因: 書き出しは、位置や拡大に keyframe のある clip へ crop の filter（qtcrop）を付ける。crop が 0 でも付く
（`attach_export_crop` は motion の frame があれば付ける）。MLT の qtcrop は画像を `QPainter` で描き直す
（`filter_qtcrop.cpp`）。Qt の描画は内部で premultiplied の色を使うので、半透明で色の付いた texel の RGB が
往復で変わる。黒い字形（RGB が 0）は変わらないが、赤い強調（#CC2222）は変わる。
MLT の affine が受け取る画像は、この描き直した後のものだった。演算の順や丸めの違いではない。

修正: 合成器へ渡す layer の画像を、MLT が実際に使う画像（qtcrop が付く clip は描き直した後）にする。
これは合成の計算の外の前処理で、Qt を使う（合成の核には入れない）。書き出しから qtcrop を外す方法は、
現在の画素を変えるので採らない。許容差は足していない。

確かめていないもの: MLT を診断用に作り直して内部の値を見ることはしていない（上の切り分けで足りた）。
この画素の補間の中間値（素材座標の端数、周りの texel、重み）は記録していない。

## 2. 合成器（Task B）

`src/media/math/math_group_compose.{h,cpp}`（`mvm::math::composeMathGroup`）。

- MLT・Qt に依存しない。状態を持たない。入力は POD の配列。
- straight alpha の RGBA8（R, G, B, A の順）。layer は下から順に重ね、1 枚ごとに 8 bit へ切り捨てる。
- 等倍だけ。layer は出力と同じ大きさで、左上を倍精度の位置へ置く。素材座標は MLT と同じ足し方
  （先頭の値に 1.0 を足し続ける）で求めて binary32 へ落とし、以降は binary32 で計算する。
  演算は 1 つずつ binary32 に確定させる（まとめられると結果が変わるため）。
- 素材座標が範囲に入る出力画素だけを書く（はみ出した分は描かない）。
- 字形の範囲（alpha が 0 でない texel の外接矩形）の近くだけを走査する。MLT は字形の無い画素でも下の alpha を
  書き直すが、その書き直しが 0〜255 のすべてで元の値に戻ることを確かめたうえで飛ばす
  （`mathGroupAlphaRoundTripIsIdentity`。この環境では恒等だった。恒等でなければ全画素を走査する）。
- 拡縮・回転・shear・crop・大きさの違う layer・範囲外の不透明度は拒否する。
- メモリ: 出力の尺に比例する確保は無い。1 回の呼び出しで、layer ごとに幅と高さ分の座標の配列を作る。
  **layer の画像は全画面のまま持つ**（字形の範囲に切った画像を持つ形にはしていない）。
- 上下とも alpha 0 の画素は書かない。MLT では 0 での割り算になり、結果が定まらない。不透明な下地の上では
  起きない。この場合の MLT との一致は確かめていない [未検証]。

## 3. 検証（Task C）

**独立した oracle との比較**（`math_group_compose_oracle`、CTest）。期待値は既存の `mlt_rgba_oracle.h` で作り、
合成器の関数は使わない。oracle は補間なしの source-over なので、ここで確かめるのは整数位置である。

[事実] 40 通り（1〜5 layer、重なり、出力の端からのはみ出し、不透明度 0・25・33.33・50・75・100%、
透明・半透明・不透明の texel）で、491,520 byte がすべて一致した。字形の範囲だけを走査した結果も同じだった。
下地は不透明（alpha 255）だけを試している。

**実際の MLT の pre-YUV との比較**（`mvm_math_score_export_parity --reference-mode 9`）。baseline は製品の
書き出し。全画素・4 channel、許容差なし。

[事実] 9 fixture・代表 frame 20 枚がすべて完全一致した（`pure-compositor/`）。

| fixture | 比べた frame | layer | 内容 |
| --- | --- | --- | --- |
| `cmp-integer` | 3 | 1 | 整数位置、最終 frame を含む |
| `cmp-fraction-fade` | 2 | 1 | 端数位置 |
| `cmp-layers-16`・`cmp-layers-48` | 2・1 | 16・48 | 同じ位置に重なる layer |
| `cmp-region-motion` | 3 | 25〜29 | v4 の 20〜22 秒、字幕を含む。差のあった frame 96 を含む |
| `cmp-region-scale` | 1 | 37 | v4 の 88〜91 秒 |
| `p2-window-early`・`middle`・`late` | 3・3・2 | 25・41・25 | v4 の前半・中盤・後半 |

比べていないもの（一致に数えていない）:

- 代表 frame 以外の frame。補間の途中と fade の途中の frame は、値を独立に求めていないので比べていない。
- 拡縮する layer を含む frame（合成器が拒否する）。
- 不透明度 0% と 100% の間の値・fade は、単体試験（整数位置）では確かめたが、MLT との比較では
  その frame で保持されている値だけである。

## 4. 計測（Task D）

`mvm_test_math_group_compose bench`（1920x1080、1 thread、20 frame の平均。`pure-compositor/microbench.txt`）。

| 条件 | ms/frame | 走査した画素/frame | ns/画素 |
| --- | --- | --- | --- |
| 1 layer、字形 532x20、整数位置 | 0.235 | 11,193 | 21.0 |
| 1 layer、字形 532x20、端数位置 | 0.231 | 11,193 | 20.6 |
| 16 layer、532x20、端数、重なり | 3.708 | 179,088 | 20.7 |
| 40 layer、532x20、端数、重なり | 9.279 | 447,720 | 20.7 |
| 40 layer、200x60、端数、重なり | 13.984 | 490,440 | 28.5 |
| 1 layer、全画面、端数 | 34.572 | 2,070,601 | 16.7 |

[事実] 走査した画素 1 つあたり 16.7〜28.5 ns。整数位置と端数位置で差は無い（どちらも同じ補間の式を通る）。

測っていないもの: CPU 時間（経過時間だけ）、確保の回数と peak working set、合成先を事前に初期化しない場合。
この計測は合成の関数だけの時間で、書き出し全体の時間ではない。全体の所要時間は主張しない。

## 5. 対照（Task E）

単体試験の中で、入力を 1 点だけ誤らせると oracle の期待値と一致しなくなることを確かめた
（合成の失敗や crash ではなく、byte の不一致として検出される）。

| 対照 | 状態 |
| --- | --- |
| layer の順序 | 検出 |
| 位置の 1 画素ずれ（素材 frame の対応の誤りに当たる） | 検出 |
| 端数の位置（整数位置の期待値と違うこと） | 検出 |
| 不透明度 | 検出 |
| layer の欠落 | 検出（最初は不透明度 0 の layer を外していて検出されなかった。対照の作り方の誤りだったので、画素へ寄与する layer を外すよう直した） |
| texel の alpha | 検出 |
| 拡縮・範囲外の不透明度 | 拒否 |
| MLT との比較での frame の欠落・未検証の画素 | 既存の harness の対照（観測の欠落、期待値のずれ）がある。今回は再実行していない |
| **source-over の丸めの誤り** | **未実施** |
| 範囲の外へはみ出した字形の扱い | 期待値との一致で確かめた。誤らせる対照は作っていない |

## 6. 次

1. MLT との比較を全 frame へ広げる（補間の途中・fade の途中を含む）。位置と不透明度は書き出しの計画の値を使う。
2. 丸めを誤らせる対照と、はみ出しを誤らせる対照を足す。
3. layer の画像を字形の範囲だけで持つ形にする（範囲の外の texel が完全に透明であることの検査を含む）。
4. qtcrop の描き直しを、Qt を使う前処理として書き出しの staging 側に置く設計を決める。
5. そのうえで P3-3（MLT 層への組み込み、既定は無効）へ進むかを判断する。
