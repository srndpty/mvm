# P3-3C: 準備済みの数式の画像を、中身のある範囲だけで持つ

2026-10-12。[P3-3B](math-transition-p33b.md) の診断用の数式 group は、clip ごとに全画面の RGBA（7.9 MB）を
持っていた（v4 の Project で 783 MB）。これを、中身のある範囲の画素だけを持つ形に替えた。

**結果は PASS（診断用の経路として）。** v4 の Project 全体の graph で、準備済みの画像は 783 MB → 2.81 MB、
process の peak は製品の経路より約 200 MB 少なくなった（P3-3B は約 600 MB 多かった）。pre-YUV は、製品の経路・
全画面で持つ形・範囲だけで持つ形の 3 つが、比べた全 frame で一致した。

製品の書き出しの経路と timeout、MLT の affine、既存の画素 oracle、下地の alpha の契約（1 以上）は変えていない。
alpha 0 の下地を扱う仕組みは足していない。v4 の Project 全体（6840 frame）の書き出しは行っていない。
commit・push はしていない。P1〜P3-3B の成果物と判定は変更していない
（`math_equation_sequence_product_ui` の SegFault は未解決のまま）。

証拠は `build/math-transition-p33c-20261012/`。最終の run は 3 つに分けて実行した
（`…-final-fixtures/`、`…-final-windows/`、`…-final-timing/`。どれも同じ source・binary で、
`identity.json` に SHA-256 がある）。

## 1. 持ち方と座標（Task A）

`PreparedMathRaster`（`src/media/math/math_group_compose.h`）が持つもの:

| 項目 | 内容 |
| --- | --- |
| 元の画像の大きさ | `width()`・`height()`（出力と同じ大きさの全画面） |
| 座標の原点 | 元の画像の左上。保存した範囲の位置は、いつも元の画像の texel 座標で表す |
| 保存した範囲 | `storedX/Y/Width/Height`。**どれかの byte が 0 でない texel** の外接矩形 |
| 画素 | 保存した範囲の RGBA だけ（行間の余白なし、`storedWidth × storedHeight × 4` byte） |
| 字形の範囲 | `roiX/Y/Width/Height`。alpha が 0 でない texel の外接矩形（保存した範囲の中にある）。走査する出力画素を決める |
| 範囲の外 | 4 byte とも 0。準備が全画素を走査して範囲を決めるので、必ず成り立つ |
| 照合用の値 | 元の画像の全画素（大きさを含む）から求めた 64 bit の値。持ち方が違っても同じ |
| 出どころ | 成果物の path と前処理（`none` / qtcrop と同じ描き直し）の文字列 |

- 保存した範囲を「左上が (0, 0) の小さい画像」としては扱わない。合成器は、素材座標・補間の位置・重みを
  元の画像の座標のまま求める（全画面で持つ場合と同じ式、同じ binary32 の丸め、同じ端の扱い）。
  違うのは texel の読み方だけで、保存した範囲の中なら保存した画素、外なら (0, 0, 0, 0) を読む。
- **alpha が 0 で色が 0 でない texel は捨てない。** MLT は色を alpha と独立に補間するので、そういう texel は
  縁の画素の色に効く。保存する範囲を「alpha が 0 でない」ではなく「どれかの byte が 0 でない」で決めることで、
  範囲の外は色も含めて 0 になり、持たなくても元の画像と同じに読める。数式の画像（背景が透明）では、
  2 つの範囲は同じになる。
- 作った後は変えられない。複製は同じ画素を共有する。外から範囲を渡す口は無い。
- 全画面で持つ形（`MathRasterStorage::FullFrame`、P3-3B までの形）は、比較の基準として残してある。
- 1 画素の合成の式（P3-1.2）は 1 つの関数にまとめ、2 つの持ち方で共有している。式と丸めは変えていない。

## 2. 単体での検証（Task B）

`math_group_compose_oracle`。範囲だけを持つ画像の合成を、(1) 全画面で持つ画像の合成、(2) 元の画素を
全部走査する入口（範囲の指定なし）の 2 つと比べ、全 byte の一致を見る（3,846,144 byte）。

| 見たもの | 内容 |
| --- | --- |
| 範囲の縁と、その 1 画素外 | 不透明な 1 texel を半画素ずらすと、ちょうど 2 × 2 画素が変わる |
| 端数の位置 | 0.36・0.5・0.999 などの組み合わせ |
| 大きな正負のずれ | ほとんど外へ出る位置、完全に外へ出る位置（幅・高さを超える） |
| 空の画像・幅 1 画素の字形・1 texel の字形 | 空の画像は画素を持たず、合成は何も変えない |
| 画像の端に掛かる字形 | 左上の角と右下の角 |
| 重なる複数の layer、fade の途中の不透明度 | 6 層。不透明度 0 を含む |
| 色の付いた半透明の字形 | qtcrop の描き直しの後のように、色が alpha に応じて落ちたもの |
| alpha 0 で色のある texel | 字形の外にある場合（保存する範囲に入ることも確かめる） |
| 下地の alpha | 255、254、1、1〜255 の乱数 |

ほかに、元の画像の座標で読むと 2 つの持ち方が元の画素と同じになること（画像の外は 0）、1 byte でも違う画像は
照合用の値が違うこと、生きている画素の byte 数が解放で元へ戻ること、字形の範囲が保存した範囲から
はみ出す指定を拒否することを確かめている。

## 3. memory と所有（Task C）

- 準備は stage のとき（PNG を作るのと同じ画素から）に行い、全画面の複製は残さない。P3-3B は、準備の元に
  なる全画面の画素を全 clip 分いったん持っていた。
- 準備するのは、配置が対象になりうる mapping の clip だけである（書き出しの計画から判定する）。
  P3-3B は、対象外の 2 clip（拡縮する）の分も準備していた。MLT の層の最終の判定は変えていない。
- 同じ成果物・同じ見た目（記法・式・文字の大きさ・色・背景色）・同じ前処理の画像は、1 回だけ準備して
  共有する。v4 では 97 clip に対して 81 枚になる。
- frame の数に比例する保存はしていない。cache も足していない（書き出し 1 回の間だけ持つ）。
- 画像は、書き出しを呼ぶ側が関数から戻るまで保持する。render worker は読むだけである。

[事実] v4 の Project 全体の graph（`…-final-timing/`、別々の process）:

| | 製品の経路 | 全画面で持つ | 範囲だけで持つ |
| --- | --- | --- | --- |
| 準備した画像 | — | 81 枚 | 81 枚 |
| 画像が持つ画素 | — | 640.72 MB | **2.81 MB** |
| 準備のために走査した元の画素 | — | 641 MB | 641 MB |
| stage が終わった時点の working set | 約 100 MB | 約 742 MB | 約 104 MB |
| process の peak（4 区間） | 1,431〜1,567 MB | 1,871〜1,919 MB | **1,224〜1,282 MB** |
| 書き出しの後に生きている画素 | — | 0 | 0 |

- P3-3B（99 枚、783 MB）と比べると、画像は 783 MB → 2.81 MB。全画面で持つ形も、準備する枚数が減った分
  （99 → 81 枚）だけ 641 MB になっている。
- 範囲だけで持つ形の peak は、製品の経路より約 200 MB **少ない**。group にした 97 clip を MLT が画像として
  開かなくなるためと考えられる [推測]。
- 取消・失敗の後も、生きている画素は 0 だった（下の対照）。取消の後の working set は約 308 MB で、
  正常に終わった後（約 330〜380 MB）と同じ程度である。
- 準備済みの画像の上限（observer の入力）は、範囲だけで持つ形の既定を 64 MB にした（実行の前に固定。
  実測は 2.81 MB）。全画面で持つ形は 800 MB のままである。

## 4. 画素の一致（Task D）

`pwsh scripts/math-transition-p33c-verify.ps1`。3 つの経路:

- B: 製品の経路（変更なし）
- F: 数式 group、準備済みの画像は全画面（P3-3B の形）
- R: 数式 group、準備済みの画像は範囲だけ

fixture ごとに、F と R をそれぞれ別の process で「B → candidate → B」の順に書き出し、candidate の全 frame の
全 byte を B と比べる。2 つの process の B が同じであることは、B の全 frame の digest の一致で確かめた。

[事実]

| fixture | frame | F | R | group にした clip | 画像（F / R） |
| --- | --- | --- | --- | --- | --- |
| `cmp-integer`・`cmp-fraction-fade` | 120 ずつ | 一致 | 一致 | 1 | 7.91 MB / 0.03 MB |
| `cmp-layers-16` | 120 | 一致 | 一致 | 16 | 110.74 / 0.21 |
| `cmp-layers-48` | 120 | 一致 | 一致 | 48 | 316.41 / 0.93 |
| `cmp-region-motion` | 120 | 一致 | 一致 | 28 | 174.02 / 0.41 |
| `cmp-region-scale`（従来の layer と混ざる） | 180 | 一致 | 一致 | 34 | 253.12 / 1.54 |
| `p2-window-early`・`middle`・`late` | 60 ずつ | 一致 | 一致 | 24・40・24 | 158〜301 / 0.36〜0.97 |
| `alpha-255`・`254`・`253`・`128`・`1`・`all-nonzero` | 120 ずつ | 一致 | 一致 | 16 | 110.74 / 0.21 |
| Project 全体の graph、4 区間 | 60 ずつ | 一致 | 一致 | 97 | 640.72 / 2.81 |

- 19 の fixture・区間、1,920 frame。F・R とも、欠落・比べなかった frame・不一致の frame は 0。
  2 回目の B は 1 回目と全 frame 同じで、2 つの process の B の digest も全部一致した。
- 時間の計測の run（5）でも、B・F・R を別々の process で書き出した出力の digest が、4 区間とも一致した。
- digest は frame ごとの 64 bit の値（暗号学的な hash ではない）。candidate と B の比較そのものは、
  digest が違った frame を全 byte 比べている。

対照（R。`…-final-windows/`）:

| 対照 | 期待 | 結果 |
| --- | --- | --- |
| 合成を 1 frame 飛ばす | 画素の不一致 | 検出（119/120 一致） |
| 1 つ後の frame の値を使う（layer の対応） | 画素の不一致 | 検出（91/120） |
| 不透明度を半分にする | 画素の不一致 | 検出（0/120） |

| 一番上の layer を落とす（画像・layer の欠落） | 画素の不一致 | 検出（0/120） |
| 下地に alpha 0 の画素を作る | 合成器が拒否し、書き出しが失敗 | 検出。終了後の画素 0 |

| group を使う書き出しそのものを失敗させる | 失敗を返し、出力 file が残らない | 検出（終了コード 6、最終 file・一時 file とも無し、画素 0） |
| 途中で取消 | 取消で終わり、何も残らない | 検出（25 frame の後、transition・画素とも 0） |

合成器の変異（`pwsh scripts/math-transition-p33c-mutations.ps1`、`20261012-200932-mutation/`）。source を
1 か所だけ書き換え、単体試験と、実際の MLT との比較（R）の両方で検出されることを見た。4 つとも build は
成功し、source は SHA-256 が一致する形で復元した。

| 変異 | 単体試験で落ちた検査 | 実際の MLT との比較 |
| --- | --- | --- |
| 保存する画素を 1 列ずれた所から複製する（範囲の原点の誤り） | 「中央の字形: 範囲だけを持つ画像の合成は基準と同じ」 | `cmp-layers-16`: 0/120 一致、916,317 画素 |
| 左の texel が範囲の外のとき右も読まない（補間の縁の欠落） | 同上 | 同: 0/120、11,150 画素 |
| 範囲の外の texel を不透明な黒として読む | 同上 | 同: 0/120、229,311 画素 |
| 下の alpha を 255 で割る（alpha の正規化） | 「下の alpha が 254 の画素が MLT の観測値と一致する」 | `cmp-layers-48`: 114/120、6 画素（P3-1.2 の反例と同じ数） |

どれも画素の不一致として検出された（書き出しの失敗や timeout ではない）。

[未検証] 「範囲の外に alpha 0 で色のある texel がある成果物」は、実際の数式の成果物には無い
（背景が透明なら 4 byte とも 0）。この場合の MLT との一致は、単体試験（全画面で持つ形・全走査との一致）で
確かめただけで、そういう画像を実際の MLT へ通してはいない。全画面で持つ形は、どの texel の色も
そのまま読むので MLT の入力と同じである。

## 6. 安全と gate（Task F）

- 入口は observer の入力だけで、製品の書き出し（observer が NULL）からは有効にできない。
- 下地の alpha の契約（1 以上）は変えていない。alpha 0 を扱う仕組みは足していない。
- 並行: 準備済みの画像は変えられない型で、worker は読むだけである。製品と同じ worker 4 本で、
  全部の run が一致した。[未検証] data race の検出器は使っていない（P3-3A から同じ）。
- 正常終了・最初の frame での失敗・取消のどれでも、書き出しの後の「生きている transition」
  「実行中の callback」「生きている画素」は 0 だった。

| gate | 結果 |
| --- | --- |
| 合成器の単体試験（`math_group_compose_oracle`） | 通過（6,629,168 byte を比べて一致） |
| 3 つの経路の比較（4） | 通過 |
| 合成器の変異（P3-3C の 4 つ、P3-3B の 5 つ） | 9 つとも意図した検査で検出。source は SHA-256 が一致する形で復元 |
| 合成器と MLT の全 frame 比較（P3-1.2 の script。準備済みの画像は範囲だけ） | 通過（`20261012-211855-compositor-all/`。比べた 841 frame が一致、拡縮を含む 119 frame は対象外のまま、対照 4 つを検出） |
| 関連の CTest（49 件） | 49/49 通過（`ctest-final.log`） |
| lint | 通過 |
| 全 CTest | 実行していない |

provenance:

- 最終の 3 つの run は、同じ source・同じ binary（harness の SHA-256 は `41E6D703…D7C3FCEF`）で実行した。
  `identity.json` の 16 file のうち、source・script・MLT と Qt の DLL・Project の 15 file は、gate の後の
  作業 tree と一致している。
- **harness の binary だけは、今 disk にあるもの（`D2423552…C7BB6642`）と一致しない。** 最終の run の後に
  実行した P3-3B の変異の script が、source を元へ戻してから build し直したためである（この build は
  同じ source から同じ byte の binary を作らない）。source の SHA-256 は変異の前後で一致している。
- 作り直した binary でも同じ結果になることを、Project 全体の graph の 4 区間（F・R）でもう一度確かめた
  （`20261012-213406-confirm-rebuilt/`）: 8 回とも全 frame 一致で、製品の経路の全 frame の digest も
  最終の run と同じである。この run の `identity.json` は、16 file とも今の作業 tree・binary と一致している。
- 合成器と MLT の全 frame 比較（P3-1.2 の script）と CTest は、作り直した binary で実行した。
- git の HEAD は `004d0ef`（P3-3B）で、P3-3C の変更は commit していない。
- `trial/` は、script を用意する前の試しの run（harness の binary の SHA-256 だけを残している）。
- P3-1.2 の変異の script の 5 つ目は、P3-3B から動かないままである（P3-3B の文書に記載）。

## 7. 次に必要なこと
